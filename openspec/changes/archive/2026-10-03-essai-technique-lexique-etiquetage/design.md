# Technical Design: Essai technique — lexique libre et étiquetage dans le navigateur

## Approach

À déterminer pendant l'essai : c'est son objet. Deux approches au moins sont comparées derrière un même contrat (un étiqueteur est une fonction `texte -> [{mot, catégorie}]`) :

1. consultation du lexique seule ;
2. étiquetage contextuel exécuté localement (bibliothèque JavaScript ou petit modèle).

Les cinq catégories vivent dans une constante de code partagée, et les étiqueteurs s'enregistrent dans un registre commun, pour que la page d'essai et l'outil de comparaison les traitent de la même façon.

## Key decisions

- Tout le traitement du texte se fait dans le navigateur ; aucune requête ne contient le texte collé.
- Aucun compte, aucun stockage du texte.
- Le corpus de référence est annoté à la main avant tout essai d'étiqueteur, pour que la mesure ne soit pas ajustée après coup.

## Open questions

- Une simple consultation du lexique suffit-elle, ou faut-il tenir compte du contexte ? (18 octobre 2026)
- Sous quelle licence publier Potao ? (18 octobre 2026)
- Le seuil de 9 mots sur 10 est une proposition, pas une mesure de ce qu'un lecteur tolère. La relecture du PRD recommande de le calculer sur les seuls mots de contenu.
- Que faire d'un mot ambigu (« ferme ») : trancher toujours, ou signaler l'ambiguïté ? L'essai compte les mots ambigus pour éclairer ce choix.
