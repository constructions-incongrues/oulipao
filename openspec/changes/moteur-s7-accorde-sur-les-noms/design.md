# Technical Design: Moteur S+7 accordé sur les noms

## Approach

Architecture hexagonale, en TypeScript strict :

| Couche | Emplacement | Contenu | Dépend de |
|---|---|---|---|
| Domaine | `src/domain` | découpage en mots, catégories, comparaison, et le moteur S+7 (`s7/substitution.ts`, `s7/elision.ts`, `s7/agreement.ts`, `s7/determiners.ts`, `s7/engine.ts`) | rien |
| Ports | `src/ports` | `Tagger`, `MorphologyRepository` | types du domaine |
| Adaptateurs | `src/adapters` | étiqueteurs (lexique, fr-compromise, CamemBERT), morphologie lue dans le fichier dérivé | ports |
| Interface | `src/ui` | page d'essai | domaine, adaptateurs |

Le moteur enchaîne trois étapes pures :

1. **Substitution** : pour chaque nom, n-ième lemme suivant dans la liste triée des noms, remis au nombre d'origine.
2. **Accord** (mode « réaccord » seulement) : le déterminant et les adjectifs épithètes contigus prennent le genre du nouveau nom.
3. **Élision et contraction** (les deux modes) : selon l'initiale du premier mot du groupe nominal.

Le domaine reçoit la morphologie par le port `MorphologyRepository` et des mots déjà étiquetés ; il ne connaît ni le lexique Grammalecte ni aucun étiqueteur. Ses tests utilisent un port factice en mémoire.

## Key decisions

- Le code existant de l'essai technique (JavaScript, identifiants français) est migré avant tout : TypeScript, couches hexagonales, symboles en anglais. Les scores de l'essai servent de test de non-régression.
- Entités validées par schémas : zod. Chaque entité (`Category`, `TaggedWord`, `ReferenceText`, entrées de lexique et de morphologie, `Substitution`, `S7Options`) est un schéma dont le type est déduit ; les adaptateurs valident tout ce qu'ils lisent, le domaine valide les options qu'il reçoit.
- Outillage : `tsc --noEmit` vérifie les types ; `esbuild` produit `dist/page.js` pour le navigateur (zod étant une dépendance d'exécution, il faut un assemblage) ; les tests tournent directement sur les `.ts` avec `node --test`, qui vérifie aussi le seuil de couverture. Dépendances ajoutées : `zod`, `typescript`, `esbuild`, `@types/node`.
- Couverture : seuil de 90 % sur lignes, branches et fonctions. Le périmètre est `src/`. Deux exclusions nommées : le chargement du modèle CamemBERT (111 Mo) et le branchement de la page sur le DOM ; leur logique est extraite en fonctions pures testées.
- Les valeurs de catégorie deviennent anglaises dans le code (`noun`, `verb`…) ; les libellés affichés et les fichiers de référence annotés restent en français.

- Données : un fichier dérivé du lexique Grammalecte v7.7 (MPL 2.0) pour les noms et adjectifs ; la table des déterminants est écrite à la main, elle est petite et fermée.
- H aspiré : vérifié le 2026-10-03, le lexique le distingue (note `pel` pour « héros », `hm` pour « horloge »).
- Ordre alphabétique : celui du dictionnaire français, `Intl.Collator('fr')`. Choix de l'assistant, à confirmer.
- Dictionnaire par défaut : tous les noms du lexique (54 233 lemmes), sans filtre. Confirmé par le fondateur le 2026-10-03, y compris pour les mots rares, grossiers ou mal formés.
- Tout s'exécute dans le navigateur ; aucune requête ne contient le texte. Pas de modèle génératif, pas de tirage aléatoire.
- Réaccord étendu (décision du fondateur du 2026-10-03) : adjectifs coordonnés ou apposés, attribut du sujet après un verbe d'état, participe après être, pronom sujet de reprise quand l'antécédent est sans ambiguïté dans la phrase. Sans analyse syntaxique : ce sont des règles de voisinage (`src/domain/s7/syntax.ts`), prudentes là où une erreur créerait une faute absente de l'original.
- Table des déterminants étendue aux déterminants variables en genre (certain, quel, tout, aucun, nul, tel…).

## Open questions

- Le réaccord limité aux contigus suffit-il à tenir 90 % ? C'est le pari que la mesure doit trancher ; sinon le S+7 strict est reporté.
- Que faire d'un nom mal étiqueté en amont (environ 1 mot sur 30 avec le modèle neuronal) ?
- Effort : 7,5 jours estimés avec la migration, contre une taille M dans la roadmap.
