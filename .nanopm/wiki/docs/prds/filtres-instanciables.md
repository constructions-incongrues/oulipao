# PRD: Filtres instanciables, ciblables et chaînables
Generated by /pm-prd on 2026-10-03
Project: oulipao
Status: DRAFT

Note : planification sur un concept produit en brouillon.

---

## Problem Statement

Le fondateur, persona principal, veut empiler des contraintes sur les pistes d'un texte comme on empile des effets. Aujourd'hui, chaque contrainte n'existe qu'une fois et sa piste est fixée par son type : le S+7 vise les noms, le lipogramme toutes les pistes, et l'ordre de la chaîne ne fait que s'inverser. Le geste oulipien canonique, le M±n (S+7 sur les noms, A+3 sur les adjectifs dans le même texte), est donc impossible, comme deux réglages d'une même contrainte ou un lipogramme limité aux noms.

Aucun retour d'utilisateur : le persona est le fondateur, et la demande vient de lui (jam du 2026-10-03).

---

## User Stories

- En tant que fondateur, je veux brancher deux S+n avec des décalages différents, l'un sur les noms, l'autre sur les adjectifs, pour jouer du M±n dans un même texte.
- En tant que fondateur, je veux choisir sur quelles pistes agit chaque filtre (un lipogramme sur les seuls noms, par exemple), pour doser la contrainte.
- En tant que fondateur, je veux voir la chaîne dans l'ordre où elle s'applique et la réordonner, pour comprendre pourquoi un filtre défait ce qu'un autre a fait.

## Scope

### In scope (v1)
- Une instance de filtre : un type, un identifiant, en marche ou coupée, ses réglages, ses pistes visées.
- Ajouter une instance d'un type existant (S+n, lipogramme), la dupliquer, la retirer.
- Choisir les pistes visées par chaque instance, parmi celles que son type sait traiter : S+n sur les noms et les adjectifs ; lipogramme sur n'importe quelle piste.
- Une seule chaîne en série, affichée dans l'ordre où elle s'applique ; changer la place d'une instance.
- Chaque piste de la table de mixage montre les instances qui la visent.
- Résumé, annonce et mention copiée décrivent chaque instance active et ses pistes.

### Out of scope (v1)
- Enregistrer une chaîne nommée (préréglage) — la chaîne vit le temps de la page ; le carnet la note avec chaque texte. Revisit when le fondateur refait trois fois la même chaîne à la main.
- De nouveaux types de contraintes — ce PRD porte sur les filtres, pas sur les contraintes. Revisit when les filtres sont en place (roadmap, NEXT).
- Une chaîne par piste — le S+n réécrit les autres pistes (réaccord) ; deux chaînes parallèles se marcheraient dessus. Revisit when une contrainte ne touche réellement que sa piste.

## Requirements

### Functional requirements
1. Un type de contrainte déclare les pistes qu'il sait traiter et ses pistes visées par défaut : S+n, noms et adjectifs (noms par défaut) ; lipogramme, les cinq pistes (toutes par défaut).
2. L'état de la table est une liste ordonnée d'instances ; chaque instance porte un identifiant, son type, son état (en marche ou coupée), ses réglages et ses pistes visées, validés par un schéma zod.
3. L'utilisateur ajoute une instance d'un type, la duplique ou la retire ; une instance ajoutée prend les réglages et les pistes par défaut de son type et se place en fin de chaîne.
4. L'utilisateur choisit les pistes visées d'une instance parmi celles de son type ; au moins une.
5. Le S+n visant les adjectifs remplace chaque adjectif par le n-ième adjectif qui le suit dans le dictionnaire, au même genre et au même nombre.
6. Un filtre ne touche que les mots de ses pistes visées, à l'exception du réaccord qu'entraîne un nom remplacé (déterminants, adjectifs, attributs, pronoms).
7. La chaîne s'applique en série dans l'ordre affiché ; l'utilisateur change la place d'une instance ; le texte se met à jour sans nouvel étiquetage.
8. Chaque piste de la table de mixage montre les instances qui la visent.
9. Le résumé et la mention copiée décrivent chaque instance active avec ses pistes : « — S+7 sur les noms · S+3 sur les adjectifs · lipogramme en e (Oulipao) ».

### Non-functional requirements
- Mise à jour en moins d'une demi-seconde pour un texte de 200 mots et cinq instances.
- Contraintes du projet : TypeScript strict, architecture hexagonale, entités validées par schémas zod, couverture supérieure à 90 %.

## The One UX Decision

Où vivent les instances ? Option A : un rack unique, sous la table de mixage, qui liste les instances dans l'ordre de la chaîne (chacune avec ses pistes en pastilles), les pistes ne montrant qu'un rappel de qui les vise. Option B : chaque instance s'affiche dans la tranche de chaque piste qu'elle vise, comme un insert de MAO, l'ordre global restant ailleurs.

L'option A dit la vérité du modèle (une seule chaîne en série) et ne duplique pas les réglages ; l'option B est plus proche de la métaphore de MAO, mais une instance qui vise trois pistes apparaîtrait trois fois et ferait croire à des chaînes par piste. **Décision du fondateur, 2026-10-03 : option A, le rack unique.**
